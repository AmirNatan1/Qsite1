# Phase 6-R1 environmental limitations

## PHYSICAL IOS SAFARI — NOT AVAILABLE TO EXECUTION ENVIRONMENT

No connected or already-authorized physical iOS device, device bridge, or real-device testing entitlement was available to this execution environment. No account was created, trial started, software purchased, or private material uploaded to a third-party service.

## What was attempted

The R1 validation uses the installed Windows browsers, headed Chrome, Chromium, Firefox, Playwright WebKit, persistent profiles, browser automation, and safe host-side input and lifecycle methods where available. The evidence ledger records any supplied physical recording separately and never treats a machine recording, WebKit layout proxy, or native Windows input injection as physical iPhone evidence.

## Machine proxy evidence

The package may contain clearly-labelled WebKit / iOS-layout proxy, genuine installed-Chrome zoom, and native Windows input-injection evidence. These validate their own stated machine conditions only; none is relabelled as a physical Safari or human tactile-device PASS.

## What remains unproven

Physical iPhone Safari touch, momentum, orientation, background/foreground, and Maradin lifecycle behavior remain unproven until actual device evidence is independently reviewed. Human tactile mouse or trackpad behavior also remains distinct from host-side native input injection.

## Why no production defect is inferred

An unavailable hardware condition is an environmental limitation, not evidence of a user-facing defect. Production source remains unchanged unless an independently reproducible defect is observed.
